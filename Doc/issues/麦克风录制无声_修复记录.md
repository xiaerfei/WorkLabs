# 麦克风录制 / 推流无声 — 修复记录

> 状态：✅ **已修复**（代码改动 + 编译通过），⏳ **待实测验证**（录 mp4 → ffprobe）
> 日期：2026-06-09 ｜ 改动文件：`WorkLabs/UI/WLStreamViewController.m`

---

## 1. 现象

最典型的直播组合「**摄像头画面 + 麦克风声音**」，录制出来的 mp4 / 推流**没有声音**。
但 app 运行时**扬声器能听到**麦克风的声音 —— 即「监听正常、录制无声」。

## 2. 根因

录制（`WLRecorder` mp4）与推流（`WLPusher` rtmp）共用一个**共享编码器 `WLEncoder`**（编一次、分发多路）。编码器启动时由参数 `audioEnabled` 决定**建不建 AAC 编码路**：

```objc
[self.encoder startWithVideoSize:... config:... audioEnabled:[self hasAudioCapableSource]];
```

而 `hasAudioCapableSource`（`WLStreamViewController.m`）**只认媒体文件源 `WLMediaSource`，漏了麦克风源 `WLMicSource`**：

```objc
// 旧（有 bug）
- (BOOL)hasAudioCapableSource {
    for (id<WLStreamSourceProtocol> s in self.sidToSource.allValues) {
        if ([s isKindOfClass:[WLMediaSource class]]) return YES;   // ← 只认媒体文件
    }
    return NO;
}
```

于是「只有摄像头 + 麦克风、没有媒体文件」时：

1. `hasAudioCapableSource == NO` → `audioEnabled == NO`
2. `WLEncoder` 不执行 `setupAudio`，**不建 AAC 路**
3. 混音帧虽经 `audioBufferOutput → appendAudioSampleBuffer:` 送到编码器，但一进门就因 `!_audioEnabled` 被直接丢弃（`WLEncoder.m:144`）
4. 结果：mp4 只有视频流，**无音频流**

**大白话**：声音的管子（采集 → 混音 → 播放）是通的，所以你能从扬声器听到；但通往「录制/推流」那根支管的**阀门（`audioEnabled`）被错误地关着** —— 开阀门的判断只看「有没有放视频文件」，没看「有没有插麦克风」。

> 同文件 `:577`（给设置面板列音量条）却正确地把麦克风算作有音频（`fromType == WLFromTypeMedia || == WLFromTypeMic`）—— 两处判断不一致，坐实了这是**遗漏**。

## 3. 修法

把 `hasAudioCapableSource` 改为按 `fromType` 判定，与 `:577` 完全统一：

```objc
// 新（已修）
- (BOOL)hasAudioCapableSource {
    for (id<WLStreamSourceProtocol> s in self.sidToSource.allValues) {
        if (s.fromType == WLFromTypeMedia || s.fromType == WLFromTypeMic) return YES;
    }
    return NO;
}
```

- **风险低**：`fromType == Media` 仍返回 YES，原「媒体文件录制有声」路径不受影响；只是把麦克风也纳入。
- **编译**：`xcodebuild -workspace WorkLabs.xcworkspace -scheme WorkLabs -configuration Debug` → **BUILD SUCCEEDED**。
- 无增删文件，**不需** `xcodegen` / `pod install`。

## 4. 验证（待实测）

录一段「摄像头 + 麦克风」mp4，跑：

```bash
ffprobe -hide_banner -v error \
  -show_entries stream=index,codec_type,codec_name,sample_rate,channels,duration \
  -of default=noprint_wrappers=1 "你的录制.mp4"
```

**通过标准**：
- 出现 `codec_type=audio` / `codec_name=aac`（音频流写进去了 = 修复生效）；
- `audio duration ≈ video duration`（差 < 0.2s，粗判无明显 drift）。

回归：再录一段**仅媒体文件**的，确认仍有声（`fromType==Media` 仍返回 YES）。

## 5. 关联问题（未在本次处理）

1. **隐患 B（音视频同步精度，未修）**：音频 pts 用**累计样本数**推进（`WLEncoder.m:429` `_aNextPts += 1024`），而混音器**无输入时不产帧**（`WLAudioMixer.m:203` `if (!any) return`）。音频断流（媒体文件 seek/暂停、麦克风掉数据）时，音频时间轴会**丢失那段空白时长** → 断流恢复后**音频超前于视频（A/V drift）**，且每次断流累积。持续供音场景不触发。
   - **修复方案见 [`WorkLabs设计/音频断流漂移_AV同步精度方案.md`](../WorkLabs设计/音频断流漂移_AV同步精度方案.md)**（根因＝混音器断流跳帧 `WLAudioMixer.m:203`；首选修法＝补静音帧）。OBS 对策见 [`调研/OBS/OBS_输出侧_编码_复用_录制推流.md`](../调研/OBS/OBS_输出侧_编码_复用_录制推流.md)。
2. **边缘情况（未覆盖）**：`audioEnabled` 在开录/开播**瞬间一次性决定**。若「先开录（仅摄像头）→ 录制中途再加麦克风」，AAC 路不会补建，中途加的麦克风仍录不进。
