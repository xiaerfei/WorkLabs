# 滤镜激活时内存高水位排查（120MB → 1.16GB 驻留）

> 2026-06-10，借助新加的 WLPerfMonitor（200ms 采样 CPU/内存日志）定位并修复。

---

## 1. 现象

纯预览（未录制/推流）下把**亮度拉满**（任何让滤镜激活的参数都一样），4K 10-bit HEVC 源：

```
[I][Perf] CPU   8.1% | 内存   120.0 MB   ← 基线（滤镜关，透传）
[I][Perf] CPU  46.6% | 内存   275.3 MB   ← 滑动开始
[I][Perf] CPU  32.3% | 内存  1035.3 MB
[I][Perf] CPU  19.7% | 内存  1161.9 MB   ← 平台期，此后不再涨、也不回落
```

- 增量 1042MB ÷ 33.2MB（4K BGRA 单帧）≈ **31 帧**；
- 爬升耗时 ≈1.6s，25fps × 1.2s = **30 帧** —— 两个数字都指向 `WLVideoMix` 的缓冲上限 `MAX_ASYNC_FRAMES = 30`；
- 滑回 0 后内存**不回落**，永久驻留。

## 2. 根因（三因素叠加）

1. **纯预览时合成 tick 停着，但帧照常往里投。** 合成 tick 仅在录制/推流时运行（`compositingEnabled`，节能设计）；而 fork 处无条件 `inputVideoFrame:` 给 mix → `asyncFrames` 只进不出，涨到 30 帧整盘倒掉、再涨，循环。
2. **滤镜关时没事，靠的是隐性反压。** 透传帧借自 VideoToolbox 解码器的**有限池**，池借光解码线程即停，流水线被卡在十几帧。滤镜开后输出换成滤镜**自有无上限 pool** 的全新 BGRA buffer，输入帧立刻归还解码池，反压消失 → 队列真能涨满 30 帧 ≈ 1GB。
3. **CVPixelBufferPool 只增不缩。** 倒掉的 buffer 回池缓存不还系统；且归零后滤镜实例（连同 pool）仍留在 `sidFilters` → 高水位永久驻留。

CPU 侧 8%→17-28% 为 4K 每帧 Metal 渲染（含 `waitUntilCompleted`）的预期开销；46% 尖峰是 pool 冷启动批量分配 IOSurface 的一次性成本。

## 3. 修复（已实测）

| # | 改动 | 位置 |
|---|------|------|
| A | 合成关闭时 `inputVideoFrame:` 直接丢帧（tick 不跑无人消费；`startTick` 本就清陈帧+重锚，无副作用） | `WLVideoMix.m` |
| C | 参数归 identity 时连 `sidFilters` 实例一起移除 → 输出 pool 随 dealloc 释放，归还高水位（在途帧自 retain、fork 线程经字典强引用兜底，无 use-after-free；再次调参按需重建） | `WLStreamsManager.m` |
| 附 | `isIdentity` 改阈值比较（±0.001）：精确浮点比较下滑块归零≠精确 0.0，滤镜驻留链路、C 永不触发（注：《滤镜渲染问题排查》「尝试 2」声称已合入此改动，但代码中并不存在，本次才真正落地） | `WLBasicVideoFilter.m` |

未做 B（滤镜 pool 加 `kCVPixelBufferPoolAllocationThresholdKey` 硬上限）：当前场景 A+C 已治本，需要保险时再加。

## 4. 裁剪拖动的瞬态尖峰（已分析，暂不处理）

修复后实测拖动裁剪滑块（从 0 拖到最大）：

```
[I][Perf] CPU  11.3% | 内存   231.8 MB   ← 滤镜稳态
[I][Perf] CPU  32.7% | 内存   738.3 MB   ← 拖动中峰值
[I][Perf] CPU  12.4% | 内存   253.0 MB   ← 松手 ~1s 后回落
```

**与高水位问题本质不同：瞬态、有界、自恢复，不是泄漏。**

成因：裁剪改输出尺寸，pool 按尺寸建、量化到 16px 桶（`WLBasicVideoFilter.m`）。4K 宽 3840px，裁剪 0→0.45 要扫过 ~108 个桶——快速拖动时几乎每帧落新桶 → pool 每帧重建、零复用，每帧都是全新 25~33MB buffer，等预览层消费完才释放 → 拖动期间堆出数百 MB 在途库存。护栏（预览层 2 帧在途背压 + 修复 A）保证了上限与回落。

若将来要进一步削峰（如低配机型），备选：
1. **拖动期间锁定输出尺寸**：滑动中只改 shader 采样区间，松手才重建 pool——尖峰基本消失，需把「正在拖动」状态从 UI 传下来；
2. **加粗量化桶**（16px → 64/128px）：一行改动，尖峰同比例下降，代价是裁剪输出宽高比粒度变粗。
