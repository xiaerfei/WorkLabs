## `reset` 与 `resampleFrame:NULL` 区别

这个问题问到点子上了！答案是：**完全不一样，它们的效果甚至可以说是“截然相反”的。** 这是音频开发中非常经典的一个概念区分，它们分别对应了不同的业务场景。我们可以用一句话来概括它们的本质区别：

> - **`reset`** 是为了**丢弃**（Discard）缓存。
> - **`[resample resampleFrame:NULL]`** 是为了**榨干**（Drain/Flush）缓存。

------

### 1. 深入对比

为了让你一眼看清它们的区别，我做了一个对比表：

| **特性**         | **reset (调用 swr_init)**                                  | **[resample resampleFrame:NULL]**                  |
| ---------------- | ---------------------------------------------------------- | -------------------------------------------------- |
| **核心目的**     | 瞬间清空重采样器内部残留的数据，不留痕迹。                 | 告诉重采样器“没新数据了，把肚子里剩下的都吐出来”。 |
| **数据去向**     | 内部残留的几百个采样点被**直接丢弃**，不返回。             | 内部残留的数据被正常重采样，并**返回给你**。       |
| **典型场景**     | **Seek（跳转进度）**、停止播放、切换歌曲。                 | **播放到文件末尾（EOF）**，准备收尾。              |
| **对听觉的影响** | 如果在正常播放中调用，声音会瞬间中断，可能有轻微“咔哒”声。 | 能完美听到文件的最后几毫秒，不会有声音被截断。     |

------

### 2. 用生活中的例子打个比方 ![🍧](https://fonts.gstatic.com/s/e/notoemoji/17.0/1f367/72.png)

想象一下你在用**原汁机（榨汁机）**榨苹果汁：

- **`[resample resampleFrame:NULL]` (Flush)**：

  你已经把切好的苹果都扔进去了。现在苹果没了，但机器的螺杆和滤网里还挂着不少果肉和果汁。这时候你**不关机器，空转几秒钟**，最后那几滴浓缩的果汁就会流进杯子里。这就是 Flush。

- **`reset`**：

  你苹果切到一半，突然不想喝苹果汁了，想改喝西瓜汁。这时候你直接**把机器拆开，用水把里面的苹果泥全冲走**，准备放西瓜。这时候你绝对不希望上一杯的苹果味混进西瓜汁里。这就是 Reset。

------

### 3. 在播放器中如何配合使用？

在我们的播放器架构中，这两个操作会出现在不同的代码分支里：

#### 场景 A：正常播放到文件结束（FFmpeg 读到文件末尾）

```objective-c
// 伪代码
if (av_read_frame(fmt_ctx, packet) < 0) {
    // 没数据了，进入收尾
    NSData *lastPcm = [resample resampleFrame:NULL];
    if (lastPcm) {
        [ringBuffer write:lastPcm]; // 把最后一点存货喂给声卡
    }
}
```

#### 场景 B：用户突然拉动了进度条（Seek）

```objective-c
// 伪代码
- (void)userDidSeekToTime:(NSTimeInterval)time {
    [ffmpeg seekTo:time]; // 告诉解码器跳过去
    [resample reset];     // 必须重置！把上一个进度的残留缓存扔掉
    [ringBuffer clear];   // 顺便把环形缓冲区里的老数据也清空
}
```
