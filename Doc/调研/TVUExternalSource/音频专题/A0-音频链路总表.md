### 2.2 `TVUOverlayAudioMixerManager`（弹幕朗读 + Overlay 网页声）

| 调用点 | 塞哪一路 | 条件 |
|---|---|---|
| `aacEncoder.mm:304` | `sourceQueue[0]` LocalCamera（**主源/节拍源**） | mic；`shouldOutputAudioStream` |
| `TVUExtAudioEncoder.mm:37`（`tvuEncodeOrMixExternalSourceAudio`） | `sourceQueue[0]` | 外部源/Accsoon 当主源；同上（SPAR-769） |
| `RTMPIngestController.mm:419` | `sourceQueue[0]` | DJI 音频当主源；同上（SPAR-765） |
| `TVUWebviewAudioOutputManager.mm:155` | `queueForSource(Overlay)` = `sourceQueue[1]` | Overlay 网页声 |
| `TVUChatTTSManager.mm:482` | `sourceQueue[kTVUOverlayMixerQueueIndexTTS]` = `[2]` | 弹幕朗读 |

**输出 index 取主源**（`.mm:366`）：`param.external_source_index = local_node->external_source_index;`

两个辅源都固定写 `-1`（`TVUWebviewAudioOutputManager.mm:151`、`TVUChatTTSManager.mm:480`），所以等价于「去向完全由主源决定」。

> 两套混音器**取值规则相反**，这是刻意的：Overlay 混音器的主源可能是 DJI(200)，取辅源的 −1
> 会被编码器整块丢掉（`.mm:363-365` 注释）。PIP/PBP 那套的语义是「外部源当主、mic 当配角」，
> 所以取辅源。**新增混音路径时先想清楚照抄哪一个。**

### 2.3 `shouldOutputAudioStream` 是计算属性，从不被写

`TVUSnapshotManager.m:340-346`：
```objc
= webManager.shouldOutputAudioStream || [TVUWebChatManager manager].needsAudioMixing
```
全仓 grep 确认无 KVO、无 `valueForKey:`。TTS 那半的真相源是 `isSourceActive(TTS)`，经
`mixerStateDidChange` 回调推给 `needsAudioMixing`（`TVUWebChatManager.m:201`）缓存成 atomic
——刻意缓存，因为音频线程每帧读，不能在 getter 里走惰性链。

### 3.5 25 ms 对齐（`tvu_filter_pts_offset = 25`，`QueueManager.mm:447`）

```objc
Float64 d_offset = (mic_pts - app_pts) * 1000;                 // :504  ms
if (d_offset >=  tvu_filter_pts_offset) { 丢 app 队首; return; }  // :506  mic 领先 ⇒ 丢 app
if (d_offset <= -tvu_filter_pts_offset) { 丢 mic 队首; return; }  // :513  app 领先 ⇒ 丢 mic
// -25 < d_offset < +25 → 进 mix()
```
`getCurrentNodePts()` 空队列返回 `-1`，任一为 `-1` 整段跳过（`:503`）。

**单路降级**（`:464`）：`(app_size<=0 || mic_size<=0) && current - last_audio_mix_time > 1000`。
`last_audio_mix_time` **只在双路混音成功时刷新**（`:499`），`stopThread()` 清零（`:316`）。

**归一化系数** `tvuGetVolumeScale(getPcmDB(mic))` = `1 - db*0.015`，查表 `[0.10, 1.00]`
（`TVUAnywhereTool.h:284-327`）。语义是**用 mic 响度 duck 掉 App 音频**：`mix()` 里 mic 系数恒
1.0、app 乘 coefficient（`:602-606`）。

### 3.6 `isReceivingFrame` 的置位窗口

唯一置位 `ServerSocket.mm:125`（`didAcceptConnection`）；清位三处 `:39` init / `:59`
`disconnectSocket` / `:114` `didEndWithError`。**置位早于 delegate 回调（`:135`）**，
存在 `isReceivingFrame == YES` 但队列线程尚未 `startThread()` 的窗口，期间 mic 帧在
`addDataToScreenRecordingQueue` 第一行被静默丢弃。

### 3.7 补帧确认只在视频侧

`QueueManager.mm:562-588` 的 `addTransitionFrame()`，唯一调用点是 `encodeVideo()` 空队列分支
（`:391`），条件 `offset >= 33*3`（≈99ms）。
`TVUAVStreamManager::addTransitionFrame` **函数第一行就 `return;`**（`.mm:3224`），6 个调用点全是空操作。
`encodeAudio()` 的三个空队列分支只 `usleep(10*1000)` —— **音频侧无任何补帧/补静音**。

### 4.3 两个辅源都不产生有效 PTS

| 路 | 自填 pts | 是否被用 |
|---|---|---|
| `[0]` mic | 采集时钟 | ✅ 输出块 pts 就是它（`TVUOverlayAudioMixerManager.mm:362`） |

的注释自己点了这一条）。

## 五、一个系统性模式：`data_mix` 按首帧定长

三套前置混音器 + `AudioPlayer` 共 7 处用同一写法开混音缓冲，其中 **6 处只按第一帧的长度
malloc 一次、之后不再扩容**：

| 位置 | 写法 | 可变块长安全? |
|---|---|---|
| `TVUScreenRecordingQueueManager.mm:532` | `static uint8_t *data_mix = malloc(mic_node->param.dataSize * 2);` | ❌ 无 realloc |
| `TVUExternalSourceAudioMixerQueueManager.mm:228` | `static uint8_t *data_mix = malloc(local_node->size * 2);` | ❌ 无 realloc |
| `AudioPlayer.mm:644 / :909 / :1256 / :1323` | `static … = malloc(kTVUAudioPlayerDataByteSize * 2);` | 常量尺寸，尚可 |
| **`TVUOverlayAudioMixerManager.mm:318-330`** | 按需扩容 + `data_mix_capacity` + malloc 失败保护 | ✅ **已修好的那份** |

Overlay 那份的注释直接点名了这个坑：

> 混音缓冲按需扩容。原来是 malloc(size*2) 一次就不管了，块大小变大就会溢出。

**所以修法是现成的**，另两处照搬 `TVUOverlayAudioMixerManager.mm:318-330` 即可。
可变块长的现实来源是 DJI（块长 = `1024 × 48000 / 源 AAC 采样率` 帧）和扩展进程 App 音频
（受 `swr_get_delay` 影响）。

这与 [07 文档](../07-音频编码器-TVUAudioEncoderManager.md) §9.1–9.3 是**同一类问题**：
全链路隐含假设「一块 = 4096 字节」，但已经有生产者不满足。

## 六之三、会议音频要点（A3 摘录）

- **一个 Agora API，两种时间单位**：Partyline 走 `convertToUTCTimestampWithSystemPTS` 传 **UTC 毫秒**
  （`IntegrateAgoraTools.mm:2032`），RTIL VoIP 把 `nowTime` 原样透传传 **秒**
  （`TVURTILVoIPEngine.mm:153`）。两者共用同一个 `AgoraRtcEngineKit`，只靠 trackId 区分，
  **未找到补偿代码**。
- **二次混音的 RTIL 那支永远轮不到**：`TVUAudioEncoderManager.mm:297` 的 `voipMixWith` 先命中，
  `:306` 是 `else if`。而生产侧两家**会**同时塞 → PartyLine 混音队列只进不出，
  涨到 10 个后 `addData` 开始丢帧刷 log。
- **下行块规格 2048B / 单声道 / 48000** 贯穿全程（`enableExternalAudioSink:YES sampleRate:48000 channels:1`，
  `IntegrateAgoraTools.mm:494`）。播放器全程单声道，所以混音前必须升声道。
- **`mix()` 的动态增益 `f` 是局部变量每次调用重置**（`AudioPlayer.mm:1651`），release 状态不跨块 →
  块边界有增益跳变。
- 三个开关都是**裸全局无头文件声明**（`TVUAnywhere.mm:139/142/145`）；`enableEncoding` 纯派生无持久化，
  两个 mix 开关有 UI 与 `NSUserDefaults`，但 Lite 编译时整组 UI 被 `#if` 编掉。
