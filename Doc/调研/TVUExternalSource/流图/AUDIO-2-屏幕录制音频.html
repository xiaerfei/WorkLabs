Mic 那条扩展进程路径是死的

收发两侧都注释掉了

  • 发送侧 Client.mm:121-124 入队调用注释；线程创建 ExtendQueue.mm:177 也注释
  • 接收侧主 App MainViewController.mm:7682-7725 整段注释；IRL TVUIRLSDK.mm:443-447 是空 case
  • 原因写在 :7684：Now use audioUnit to capture
  • 屏共的 Mic 声实际来自主 App 本地采集链，经四份 static 副本之一改道进来

三家共用同一条改道

因为编码器只收 index 100

  • encode: 第一道闸门：isReceivingFrame && index != 100 → return
  • mic / Accsoon / DJI 直送都会被整块丢，所以全部改道进 mic 队列
  • 顺带吃到队列的 adjustAudioGain，所以三家都不预先施加增益
  • App 路不加增益（memcpy 原样）

25ms 门限只管音频两路之间

与视频无关

  • tvu_filter_pts_offset = 25，超门限就丢领先那一路的队首
  • last_audio_mix_time 只在双路混音成功时刷新
  • getCurrentNodePts() 空队列返回 −1，任一为 −1 整段跳过
  • ⚠️ mic 与视频之间代码里没有任何 pts 重锚
