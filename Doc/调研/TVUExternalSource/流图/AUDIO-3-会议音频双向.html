一个 API 两种时间单位

Agora 毫秒，RTIL 秒

  • Partyline：convertToUTCTimestampWithSystemPTS → UTC 毫秒
  • RTIL VoIP：nowTime 原样透传 → 秒，不经任何换算
  • 两条都调同一个 pushExternalAudioFrameRawData:…timestamp:
  • 共用同一个 AgoraRtcEngineKit，只靠 trackId 区分；未找到补偿代码

RTIL 那支混音永远轮不到

else if 被抢先

  • :297 的 voipMixWith 先命中，:306 的 RTIL 分支是 else if
  • 生产侧两家会同时塞（RTIL 在跑 + WebRTC 通话 + 两开关都开）
  • 结果 PartyLine 混音队列只进不出，10 个后开始丢帧刷 log
  • 同类问题在非主 App flavor 上更直接：照塞队列但 :275-284 永远不消费

下行块规格是硬契约

2048B / 单声道 / 48000

  • enableExternalAudioSink:YES sampleRate:48000 channels:1（:494）
  • 播放队列消费侧强校验 node->size == 2048
  • 混音队列节点也是 2048 单声道，被 encode: 消费时才升成 4096 双声道
  • mix() 的动态增益 f 是局部变量每次重置 → 块边界有增益跳变
