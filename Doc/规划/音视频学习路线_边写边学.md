### 学习方法论（铁律）

1. **盖住答案做题**：先自己用 C 写 → 卡住先查 / 问提示 → 实在不行才翻 WorkLabs → 看懂合上、再默写一遍。直接抄 = 没学到（这正是「指挥 AI 写完却没懂」的根因）。
2. **垂直切片 > 完美分层**：先打通最简端到端拿正反馈，再逐模块加深。
3. **即时补知识、绑死代码**：遇到啥补啥，补完写进代码注释 / 笔记。
4. **能跑 + 有验收基准**：每个产物都和 ffmpeg CLI / WorkLabs 输出对照（肉眼或逐字节）。
5. **费曼验真**：每模块完成后回答「为什么这么写」的自测题，答不上回炉。

### 协作协议（分工 + 我的角色）

**分工线（核心）**：
- **你写（学习重点 · C / libwl）**：解码 / 编码 / 封装、合成 mixer、音频混音 / 重采样 / 滤波 DSP、线程安全队列、时间戳与 A/V 同步、RTMP / SRT 协议、以及**抠像 / 缩放 / 色彩转换等 shader 图像算法**——一切「音视频数据怎么被处理」的逻辑。
- **我写（非重点 · OC / AppKit）**：窗口 / 视图、画布拖拽缩放、工具栏、设置面板、菜单、文件对话框，以及 Metal / AudioQueue 的**上屏、出声接线**等 UI 与平台胶水。
- **界线**：Metal 的**管线接线**（MTKView / CAMetalLayer / command buffer 提交）算平台胶水，我写；但 shader 里的**图像算法**（YUV→RGB、chroma key、Lanczos）是音视频核心，你写。`libwl` 的 C API 由**你**定义（你得清楚数据怎么进出），我把 UI 接到这些 API 上。

**我作为导师**：任务清单 + 验收标准；卡壳分级提示（方向 → 伪代码 → 参考实现）；知识点讲解；code review（bug / 内存 / 线程）；写 UI 与非主线脚手架 / 对照工具。

**验真**：你贴 C 内核代码 → 我 review + 追问「为什么」→ 通过才勾 ✅（UI 不要求你解释）。

### 里程碑详解

#### M0 · 热身　🚧 👉（开始 2026-06-15）

**产出**：能跑 FFmpeg CLI 基本操作 + 一个 C 程序解码 mp4 首帧存 BMP。

**子任务**
- [ ] `brew install ffmpeg`；把「模块 0」命令全跑一遍（提取视频/音频流、裸 YUV、裸 PCM，再用 `ffplay` 播裸数据）
- [ ] `Learning/01_decode_one_frame/decode_one_frame.c`：打开 mp4 → 解码**首帧视频** → YUV420P 转 RGB → 存 BMP
- [ ] 验收：BMP 与 `ffmpeg -i x.mp4 -frames:v 1 out.png` 肉眼一致（颜色不偏、不分裂）
- [ ] 回答自测题 → 贴代码给我 review

**必补知识**：容器/流/codec 关系 · YUV420P 内存布局 · YUV→RGB（BT.601）· `AVFormatContext`/`AVPacket`/`AVFrame` · `send_packet`+`receive_frame`

**自测题**：① `yuv420p` 一帧多少字节、怎么算？② U/V 分辨率为何是 Y 的 1/4？③ `AVPacket` vs `AVFrame` 谁是压缩的？④ 解码为何要 send+receive 两步？

#### M1 · 本地播放器　⬜

**产出**：最小播放器，播一个 mp4（画面 + 声音 + 基本同步）。
**必补知识**：PTS/DTS/time_base · 音频主时钟同步 · CVPixelBuffer→Metal 纹理（零拷贝）· AudioQueue 回调 · VideoToolbox 硬解。
**验收基准**：对比系统播放器 / ffplay——音画同步、不卡、CPU 合理（可参照 WorkLabs `WLMediaSource` 纯预览 ~11%）。
**自测题**：为何用音频做主时钟？视频追音频会怎样？time_base 是什么？硬解 vs 软解？

#### M2 · 录制器　⬜

**产出**：摄像头采集 → 实时 H264 编码 → 封装 MP4（进阶：加麦克风 AAC）。
**必补知识**：AVCaptureSession · `h264_videotoolbox` 参数（gop/bitrate/bframes）· extradata(SPS/PPS) 时序 · `av_interleaved_write_frame` · 延迟写 header。
**验收基准**：mp4 能在系统播放器播放、时长正确、有声（对照 `WLRecorder` / `WLEncoder`）。
**自测题**：为何 VideoToolbox 要首帧后才能 write_header？gop_size 与 IDR 的关系？interleaved 与普通 write_frame 区别？

#### M3 · 多源合成　⬜

**产出**：两路源（摄像头 + 文件）按位置/大小/层级合成到画布，预览 + 录制。
**必补知识**：alpha blending · 缩放（双线性）· 坐标系（画布 vs 源）· z-order · CVPixelBuffer 所有权 / pool 复用。
**验收基准**：合成画面对照 `WLVideoMix`——位置/层级正确、无残影；拖动布局实时生效。
**自测题**：alpha=0/255 各是什么效果？pool 复用为何要先铺背景（残影从哪来）？合成顺序为何是背景→各流？

#### M4 · 节拍与混音　⬜

**产出**：固定 tick 拉帧合成（替代来帧即合）+ 多源时间戳对齐 + 音频多路混音。
**必补知识**：OBS tick / 虚拟时钟选帧 · 单调钟 · 丢帧/补帧 · PCM 混音叠加 + 限幅 · 重采样统一格式。
**验收基准**：不同 fps 源混合不抖（judder）、音画长期不漂（对照 WorkLabs tick 改造 + 断流补静音）。
**自测题**：为何要 tick 而非来帧即合？快源/慢源如何对齐到合成 fps？混音直接相加会出什么问题？

#### M5 · RTMP 推流　⬜

**产出**：编码流经 RTMP 推到本地服务器（SRS / nginx-rtmp），可被拉流播放。
**必补知识**：握手 C0/C1/C2 · AMF0 · chunk stream · 序列头（SPS/PPS / AAC config）先发 · FLV tag。
**验收基准**：本地 RTMP 服务器收到流、ffplay 能拉、对照 `WLPusher`。
**自测题**：RTMP 为何握手？为何拆 chunk？为何先发 Sequence Header？

#### M6 · 工程化收尾　⬜

**产出**：OC 写 UI（画布拖拽 / 工具栏 / 设置）调用 C 内核 libwl，整合成完整 app。
**必补知识**：C↔OC 桥接（CVPixelBuffer↔wl_frame）· 跨语言内存所有权 · 线程模型。
**验收基准**：整体能采集/合成/预览/录制/推流；Instruments 无明显泄漏。
**自测题**：胶水层所有权怎么配平？哪些逻辑放 C、哪些放 OC？

#### E1 · 屏幕 / 窗口采集　⬜

**产出**：用 ScreenCaptureKit 抓整屏 / 指定窗口 / 指定 App（含应用音频），作为一路 source 接入合成 + 录制（像 camera/media 源一样）。
**必补知识**：ScreenCaptureKit（`SCStream` / `SCContentFilter` / `SCStreamConfiguration`）· CMSampleBuffer 回调 · 应用音频捕获 · 屏幕录制 TCC 权限 · 帧率/缩放配置。
**验收基准**：抓屏画面进画布合成 + 录制，清晰度/帧率对比 QuickTime 录屏；窗口源跟随窗口移动。
**自测题**：ScreenCaptureKit vs 旧 CGDisplayStream 区别？`SCContentFilter` 干什么？抓屏帧率怎么控？
**对照**：WorkLabs 无（全新源类型，复用 `WLStreamSourceProtocol` 接入）。

#### E2 · 绿幕抠像 + 滤镜链　⬜

**产出**：chroma key 滤镜（绿幕变透明）+ 滤镜可链式叠加（一个源挂多个滤镜，按序多 pass 渲染）。
**必补知识**：chroma key 算法（色距 + 边缘羽化 + 溢色抑制 spill）· GPU fragment shader · 多 pass 离屏渲染（中间纹理）· 滤镜链数据结构。
**验收基准**：绿幕人像抠干净（边缘不毛糙、无绿边）叠到背景，对比 OBS chroma key；多滤镜叠加顺序正确。
**自测题**：为何 YUV 比 RGB 更适合色键？spill suppression 是什么？多 pass 中间结果存哪、为何不直接覆盖原图？
**对照**：扩展 `WLBasicVideoFilter`（当前仅镜像/色/裁剪、单 pass）。

#### E3 · 多场景 + 转场 + 工作室模式　⬜

**产出**：多个场景（各一套源/布局）+ 场景间转场（淡入淡出/滑动）+ 工作室模式（预览场景 → 点击切到输出）。
**必补知识**：场景数据模型（scene = sources + layout）· 转场渲染（两场景同时渲染、按 progress 混合）· Studio Mode（program/preview 双输出）· 切换状态机。
**验收基准**：切场景平滑无黑屏/卡顿；转场动画流畅；工作室模式预览不影响输出流。
**自测题**：转场期间两个场景都要渲染吗？program/preview 怎么分离？Stinger 转场原理？
**对照**：WorkLabs 无（当前单画布、无场景概念）。

#### E4 · 音频滤波链　⬜

**产出**：每路音频可挂滤波链——降噪（RNNoise）、噪声门、增益、压缩器、限制器，顺序可调。
**必补知识**：音频 DSP 基础（帧/采样/dB）· 噪声门阈值/启停时间 · 压缩器 ratio/threshold/attack/release · RNNoise（神经网络降噪）集成 · 滤波链顺序。
**验收基准**：降噪后底噪明显下降、人声不失真；噪声门切掉静默；对比 OBS 音频滤镜。
**自测题**：噪声门 vs 降噪区别？压缩器 attack/release 影响什么？为何滤波顺序重要（gate→denoise→compress）？
**对照**：扩展 `WLAudioMixer`（当前仅增益/混音）。

#### E5 · 虚拟摄像头　⬜

**产出**：把合成画面输出成系统虚拟摄像头，Zoom/会议/QuickTime 能选到。
**必补知识**：macOS CoreMediaIO DAL plugin（旧）vs Camera Extension（新，`SystemExtensions`）· 跨进程帧传输（IOSurface/共享内存）· 扩展签名与安装。
**验收基准**：在 Zoom/QuickTime 选中虚拟摄像头看到合成画面；帧率/延迟可接受。
**自测题**：Camera Extension vs DAL plugin 区别？帧怎么跨进程传？为何要系统扩展权限？
**对照**：WorkLabs 曾有入口（已删）。

#### E6 · 多路输出 + 现代协议　⬜

**产出**：同时推多个目标 + 同时录制；实现 SRT 或 WHIP 之一；掉帧统计 + 动态码率。
**必补知识**：输出抽象（一个编码源 → 多 output）· SRT（基于 UDP 的可靠传输，libsrt）或 WHIP（WebRTC-HTTP ingest）· 拥塞控制/掉帧策略 · 动态码率决策。
**验收基准**：同时推两路 + 录制不卡；弱网下掉帧统计正确、动态降码率；SRT/WHIP 被对应服务器接收。
**自测题**：SRT 比 RTMP 强在哪？WHIP vs 传统 WebRTC？动态码率怎么决策？
**对照**：扩展 `WLPusher`（当前单路 RTMP）。

#### E7 · 渲染 / 图形深入　⬜

**产出**：升级合成渲染——可热加载的 effect/shader 系统、颜色空间管理（SDR/HDR/色域）、高质量缩放（Lanczos/bicubic）。
**必补知识**：shader effect 系统设计（参数化/复用）· 颜色管理（色域 primaries、传递函数 EOTF、tone mapping）· 缩放滤波（双线性 vs bicubic vs Lanczos 质量/性能）· Metal 管线深入。
**验收基准**：缩放更锐利（对比双线性）；HDR 源不过曝；加新滤镜不改主流程。
**自测题**：Lanczos 为何比双线性清晰？色域转换矩阵从哪来？HDR→SDR tone mapping 做什么？
**对照**：深化现有 Metal 合成（`WLVideoMix`）。

## 模块 1：像素格式与原始图像操作（C）

### 1.1 读取 YUV420P 文件并转为 BMP

**文件**：`yuv2bmp.c`

**功能**：读取一个 `yuv420p` 原始文件，转为 RGB，写成 BMP 文件。

**知识点**：

- YUV420P 的内存布局：Y 平面 (w×h) + U 平面 (w/2 × h/2) + V 平面 (w/2 × h/2)
- YUV → RGB 转换公式（BT.601 标准）：
  ```
  R = Y + 1.402 * (V - 128)
  G = Y - 0.344136 * (U - 128) - 0.714136 * (V - 128)
  B = Y + 1.772 * (U - 128)
  ```
- BMP 文件格式（54 字节头 + 像素数据，BGR 顺序，行对齐到 4 字节）
- 内存管理（malloc/free）

**核心代码骨架**：

```c
#include <stdio.h>
#include <stdlib.h>
#include <stdint.h>
#include <math.h>

// 1. 读取整个 YUV 文件到内存
// 2. 分离 Y/U/V 三个平面
// 3. 遍历每个像素，做 YUV→RGB 转换
// 4. 写 BMP 文件（注意 BGR 顺序和行填充）

int main(int argc, char *argv[]) {
    int width = 1280, height = 720;
    // yuv420p: Y = w*h, U = w*h/4, V = w*h/4
    int y_size = width * height;
    int uv_size = (width / 2) * (height / 2);

    FILE *fp = fopen("input.yuv", "rb");
    uint8_t *y_plane = malloc(y_size);
    uint8_t *u_plane = malloc(uv_size);
    uint8_t *v_plane = malloc(uv_size);

    fread(y_plane, 1, y_size, fp);
    fread(u_plane, 1, uv_size, fp);
    fread(v_plane, 1, uv_size, fp);
    fclose(fp);

    // 遍历每个像素
    for (int row = 0; row < height; row++) {
        for (int col = 0; col < width; col++) {
            int y_idx = row * width + col;
            // UV 是 2x2 共享的，所以索引要除以 2
            int uv_idx = (row / 2) * (width / 2) + (col / 2);

            uint8_t Y = y_plane[y_idx];
            uint8_t U = u_plane[uv_idx];
            uint8_t V = v_plane[uv_idx];

            // YUV → RGB (BT.601)
            int R = Y + 1.402 * (V - 128);
            int G = Y - 0.344136 * (U - 128) - 0.714136 * (V - 128);
            int B = Y + 1.772 * (U - 128);

            // clamp to [0, 255]
            // ... 存入 RGB buffer
        }
    }

    // 写 BMP 文件
    // ...
}
```

**编译运行**：

```bash

ffmpeg -i test.mp4 -frames:v 1 -pix_fmt yuv420p -s 1280x720 frame.yuv

# 编译并运行

# 用 macOS 预览打开 output.bmp 看结果

```

### 2.1 读取 PCM 并计算音量（RMS）

**文件**：`pcm_volume.c`

**功能**：读取一个 s16le PCM 文件，计算每一帧的 RMS 音量，输出到 CSV。

**知识点**：

- PCM s16le 内存布局：每采样 2 字节（小端），立体声交错存放
- RMS（均方根）音量计算：`sqrt(sum(sample^2) / N)`
- dB 换算：`dB = 20 * log10(amplitude / max_amplitude)`

**核心代码**：

```c
// 读取 1024 帧（frame）的立体声数据
// 一个 frame = 2 samples（左+右）× 2 bytes = 4 bytes
int16_t buffer[1024 * 2]; // 1024 frames, 2 channels
fread(buffer, sizeof(int16_t), 1024 * 2, fp);

// 计算 RMS
double sum_sq = 0;
for (int i = 0; i < 1024 * 2; i++) {
    sum_sq += buffer[i] * buffer[i];
}
double rms = sqrt(sum_sq / (1024 * 2));
double dB = 20 * log10(rms / 32768.0);
```

**编译运行**：

```bash
# 提取 PCM
ffmpeg -i test.mp4 -f s16le -ac 2 -ar 44100 output.pcm

gcc -o pcm_volume pcm_volume.c -lm
./pcm_volume output.pcm > volume.csv

# 用 Numbers/Excel 打开 volume.csv 看音量曲线
```

**知识点**：

- 削波（Clipping）：超过 ±32767 要截断
- 线性增益 vs dB：`gain_linear = 10^(dB/20)`

### 2.3 双声道混音（Mix）

## 模块 3：FFmpeg API 基础 — 解封装 + 解码（C）

**目标**：用 FFmpeg API 读取一个 MP4 文件，解码出视频帧和音频帧。

### 3.1 解封装（Demux）

**文件**：`demuxer.c`

**功能**：打开 MP4，打印每个 packet 的流索引、PTS、大小。

**知识点**：

- `AVFormatContext` — 格式上下文（打开文件、读 packet）
- `AVPacket` — 压缩数据包（一个 packet 对应一路流的一个压缩单元）
- `avformat_open_input` / `avformat_find_stream_info` / `av_read_frame`
- 流索引（stream index）：区分视频流和音频流

**核心代码**：

```c
AVFormatContext *fmt_ctx = NULL;
avformat_open_input(&fmt_ctx, "input.mp4", NULL, NULL);
avformat_find_stream_info(fmt_ctx, NULL);

// 打印流信息
for (int i = 0; i < fmt_ctx->nb_streams; i++) {
    AVStream *stream = fmt_ctx->streams[i];
    printf("Stream %d: type=%s, codec=%d, %dx%d, %d fps\n",
           i,
           av_get_media_type_string(stream->codecpar->codec_type),
           stream->codecpar->codec_id,
           stream->codecpar->width, stream->codecpar->height,
           stream->avg_frame_rate.num / stream->avg_frame_rate.den);
}

// 读取 packet
AVPacket *pkt = av_packet_alloc();
while (av_read_frame(fmt_ctx, pkt) >= 0) {
    printf("stream=%d pts=%lld size=%d\n",
           pkt->stream_index, pkt->pts, pkt->size);
    av_packet_unref(pkt);
}
```

- FLV Header（9 字节）+ Tag 结构
- Tag 类型：8=音频、9=视频、18=脚本
- Video Tag：帧类型（关键帧/非关键帧）+ 编码ID（7=AVC）
- Audio Tag：编码ID、采样率、位深、声道
- AVC Sequence Header（就是 SPS/PPS）

### 5.3 TS 包解析

**文件**：`ts_parser.c`

**功能**：读取 TS 文件，解析 PAT/PMT/PES 包。

**知识点**：

- TS 固定 188 字节包
- PAT（节目关联表）→ PMT（节目映射表）→ 音视频 PES
- PID 标识不同的流
- PCR（节目时钟参考）用于同步

## 模块 6：时间戳与同步（C + OC）

**目标**：彻底理解 PTS/DTS/时钟同步，解决实际的音视频同步问题。

### 6.1 打印并分析时间戳

**文件**：`ts_analyzer.c`

**功能**：读取一个含 B 帧的视频，打印每个 packet 的 PTS 和 DTS，画出解码序和显示序。

**知识点**：

- PTS（显示时间戳）vs DTS（解码时间戳）
- 没有 B 帧时 PTS == DTS
- 有 B 帧时 DTS 单调递增，PTS 可能跳动
- time_base 的作用：将整数 PTS 转为真实时间

### 6.2 简单的音视频同步器

**文件**：`av_sync.c`（OC，macOS）

**功能**：解码一路视频 + 一路音频，视频按音频时钟同步显示。

**知识点**：

- **音频时钟**：音频播放是匀速的（硬件时钟驱动），所以用音频作为主时钟
- **视频同步逻辑**：
  - 视频帧 PTS < 音频时钟 → 丢帧（追不上了）
  - 视频帧 PTS > 音频时钟 → 等待（还没到时间）
  - 差值在阈值内 → 正常显示
- `AVSampleBufferDisplayLayer` 的 `enqueue` 时机

## 模块 7：网络传输基础（C）

### 7.2 UDP 视频帧传输

**知识点**：

- 这就是直播拉流的基本原理

## 模块 8：RTMP 协议（C）

**目标**：理解 RTMP 协议细节，实现一个最简推流器。

### 8.1 RTMP 握手

**文件**：`rtmp_handshake.c`

**功能**：实现 RTMP 的 C0/C1/C2 握手过程。

**知识点**：

- C0/S0：版本号（1 字节）
- C1/S1：时间戳 + 零 + 随机数据（1536 字节）
- C2/S2：对端的 timestamp echo 回去
- 握手完成后进入 chunk stream

### 8.2 AMF 编码

**文件**：`amf_encoder.c`

**功能**：实现 AMF0 编码，构造 `connect`、`createStream`、`publish` 命令。

**知识点**：

- AMF0 类型标记（Number=0x00, String=0x02, Object=0x03...）
- RTMP 命令消息格式
- `connect` 命令需要携带的参数（app、tcUrl、flashVer...）

### 8.3 推送 FLV Tag 到 RTMP

**文件**：`rtmp_pusher.c`

**功能**：读取本地 FLV 文件，通过 RTMP 推送到服务器。

**知识点**：

- Chunk Stream：大消息拆分成固定大小的 chunk
- chunk basic header + message header + extended timestamp
- Sequence Header（SPS/PPS）必须第一个发
- Audio Sequence Header（AAC 配置）必须第一个发

### 8.4 完整推流器

**文件**：`rtmp_publisher.c`

**功能**：摄像头采集 → 编码 → RTMP 推流（可以复用 WorkLabs 的采集模块）。
