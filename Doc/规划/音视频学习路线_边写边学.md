## 总体策略：用 C 重写 WorkLabs 底层

### 目标

### 分层架构


## 模块 1：像素格式与原始图像操作（C）

**目标**：理解 YUV/RGB 内存布局，能手写像素级操作。

### 1.1 读取 YUV420P 文件并转为 BMP

**文件**：`yuv2bmp.c`

**功能**：读取一个 `yuv420p` 原始文件，转为 RGB，写成 BMP 文件。

**知识点**：

- YUV420P 的内存布局：Y 平面 (w×h) + U 平面 (w/2 × h/2) + V 平面 (w/2 × h/2)
- YUV → RGB 转换公式（BT.601 标准）：
  ```
  R = Y + 1.402 * (V - 128)
  G = Y - 0.344136 * (U - 128) - 0.714136 * (V - 128)
  B = Y + 1.772 * (U - 128)
  ```
- BMP 文件格式（54 字节头 + 像素数据，BGR 顺序，行对齐到 4 字节）
- 内存管理（malloc/free）

**核心代码骨架**：

```c
#include <stdio.h>
#include <stdlib.h>
#include <stdint.h>
#include <math.h>

// 1. 读取整个 YUV 文件到内存
// 2. 分离 Y/U/V 三个平面
// 3. 遍历每个像素，做 YUV→RGB 转换
// 4. 写 BMP 文件（注意 BGR 顺序和行填充）

int main(int argc, char *argv[]) {
    int width = 1280, height = 720;
    // yuv420p: Y = w*h, U = w*h/4, V = w*h/4
    int y_size = width * height;
    int uv_size = (width / 2) * (height / 2);

    FILE *fp = fopen("input.yuv", "rb");
    uint8_t *y_plane = malloc(y_size);
    uint8_t *u_plane = malloc(uv_size);
    uint8_t *v_plane = malloc(uv_size);

    fread(y_plane, 1, y_size, fp);
    fread(u_plane, 1, uv_size, fp);
    fread(v_plane, 1, uv_size, fp);
    fclose(fp);

    // 遍历每个像素
    for (int row = 0; row < height; row++) {
        for (int col = 0; col < width; col++) {
            int y_idx = row * width + col;
            // UV 是 2x2 共享的，所以索引要除以 2
            int uv_idx = (row / 2) * (width / 2) + (col / 2);

            uint8_t Y = y_plane[y_idx];
            uint8_t U = u_plane[uv_idx];
            uint8_t V = v_plane[uv_idx];

            // YUV → RGB (BT.601)
            int R = Y + 1.402 * (V - 128);
            int G = Y - 0.344136 * (U - 128) - 0.714136 * (V - 128);
            int B = Y + 1.772 * (U - 128);

            // clamp to [0, 255]
            // ... 存入 RGB buffer
        }
    }

    // 写 BMP 文件
    // ...
}
```

**编译运行**：

```bash
# 先用 ffmpeg 提取一帧 YUV
ffmpeg -i test.mp4 -frames:v 1 -pix_fmt yuv420p -s 1280x720 frame.yuv

# 编译并运行
gcc -o yuv2bmp yuv2bmp.c -lm
./yuv2bmp frame.yuv 1280 720 output.bmp

# 用 macOS 预览打开 output.bmp 看结果
open output.bmp
```

## 模块 2：音频原始数据操作（C）

**目标**：理解 PCM 内存布局，能手写音频基础操作。

### 2.1 读取 PCM 并计算音量（RMS）

**文件**：`pcm_volume.c`

**功能**：读取一个 s16le PCM 文件，计算每一帧的 RMS 音量，输出到 CSV。

**知识点**：

- PCM s16le 内存布局：每采样 2 字节（小端），立体声交错存放
- RMS（均方根）音量计算：`sqrt(sum(sample^2) / N)`
- dB 换算：`dB = 20 * log10(amplitude / max_amplitude)`

**核心代码**：

```c
// 读取 1024 帧（frame）的立体声数据
// 一个 frame = 2 samples（左+右）× 2 bytes = 4 bytes
int16_t buffer[1024 * 2]; // 1024 frames, 2 channels
fread(buffer, sizeof(int16_t), 1024 * 2, fp);

// 计算 RMS
double sum_sq = 0;
for (int i = 0; i < 1024 * 2; i++) {
    sum_sq += buffer[i] * buffer[i];
}
double rms = sqrt(sum_sq / (1024 * 2));
double dB = 20 * log10(rms / 32768.0);
```

**编译运行**：

```bash
# 提取 PCM
ffmpeg -i test.mp4 -f s16le -ac 2 -ar 44100 output.pcm

gcc -o pcm_volume pcm_volume.c -lm
./pcm_volume output.pcm > volume.csv

# 用 Numbers/Excel 打开 volume.csv 看音量曲线
```

### 2.2 简单的音量调节（Gain）

**文件**：`pcm_gain.c`

**功能**：读取 PCM，乘以增益系数，写回新文件。

**知识点**：

- 音量增益：`sample_out = sample_in * gain`
- 削波（Clipping）：超过 ±32767 要截断
- 线性增益 vs dB：`gain_linear = 10^(dB/20)`

### 2.3 双声道混音（Mix）

**文件**：`pcm_mix.c`

**功能**：读取两个 PCM 文件，混合为一个。

**知识点**：

- 混音就是对应采样相加
- 需要防止溢出（可以除以 2，或者用更复杂的归一化）
- 这就是多路音频混音的基础

## 模块 3：FFmpeg API 基础 — 解封装 + 解码（C）

**目标**：用 FFmpeg API 读取一个 MP4 文件，解码出视频帧和音频帧。

### 3.1 解封装（Demux）

**文件**：`demuxer.c`

**功能**：打开 MP4，打印每个 packet 的流索引、PTS、大小。

**知识点**：

- `AVFormatContext` — 格式上下文（打开文件、读 packet）
- `AVPacket` — 压缩数据包（一个 packet 对应一路流的一个压缩单元）
- `avformat_open_input` / `avformat_find_stream_info` / `av_read_frame`
- 流索引（stream index）：区分视频流和音频流

**核心代码**：

```c
AVFormatContext *fmt_ctx = NULL;
avformat_open_input(&fmt_ctx, "input.mp4", NULL, NULL);
avformat_find_stream_info(fmt_ctx, NULL);

// 打印流信息
for (int i = 0; i < fmt_ctx->nb_streams; i++) {
    AVStream *stream = fmt_ctx->streams[i];
    printf("Stream %d: type=%s, codec=%d, %dx%d, %d fps\n",
           i,
           av_get_media_type_string(stream->codecpar->codec_type),
           stream->codecpar->codec_id,
           stream->codecpar->width, stream->codecpar->height,
           stream->avg_frame_rate.num / stream->avg_frame_rate.den);
}

// 读取 packet
AVPacket *pkt = av_packet_alloc();
while (av_read_frame(fmt_ctx, pkt) >= 0) {
    printf("stream=%d pts=%lld size=%d\n",
           pkt->stream_index, pkt->pts, pkt->size);
    av_packet_unref(pkt);
}
```

**文件**：`video_decoder.c`

**功能**：解码视频 packet，输出 YUV420P 原始帧。

**知识点**：

- `avcodec_send_packet` / `avcodec_receive_frame` — 解码接口

**知识点**：

### 3.4 完整解码器（视频 + 音频）

**功能**：同时解码视频和音频，视频帧存为 YUV 文件，音频帧存为 PCM 文件。

**知识点**：

## 模块 5：容器格式深入（C）

**目标**：理解 MP4/FLV/TS 的内部结构。

### 5.1 手动解析 MP4 Box 结构

**文件**：`mp4_parser.c`

**功能**：读取 MP4 文件，逐个解析 Box（ftyp、moov、mdat、trak...），打印层级结构。

**知识点**：

- MP4 Box = 4字节大小 + 4字节类型 + 数据
- ftyp（文件类型）、moov（元数据）、mdat（媒体数据）
- moov 里的 trak → stbl → stts/stsc/stsz/stco（采样表）
- 为什么 moov 在文件头部比在尾部好（网络播放需要先读 moov）

### 5.2 手动解析 FLV Tag

**文件**：`flv_parser.c`

**功能**：读取 FLV 文件，解析每个 Tag 的类型、大小、时间戳。

**知识点**：

- FLV Header（9 字节）+ Tag 结构
- Tag 类型：8=音频、9=视频、18=脚本
- Video Tag：帧类型（关键帧/非关键帧）+ 编码ID（7=AVC）
- Audio Tag：编码ID、采样率、位深、声道
- AVC Sequence Header（就是 SPS/PPS）

### 5.3 TS 包解析

**文件**：`ts_parser.c`

**功能**：读取 TS 文件，解析 PAT/PMT/PES 包。

**知识点**：

- TS 固定 188 字节包
- PAT（节目关联表）→ PMT（节目映射表）→ 音视频 PES
- PID 标识不同的流
- PCR（节目时钟参考）用于同步

## 模块 6：时间戳与同步（C + OC）

**目标**：彻底理解 PTS/DTS/时钟同步，解决实际的音视频同步问题。

### 6.1 打印并分析时间戳

**文件**：`ts_analyzer.c`

**功能**：读取一个含 B 帧的视频，打印每个 packet 的 PTS 和 DTS，画出解码序和显示序。

**知识点**：

- PTS（显示时间戳）vs DTS（解码时间戳）
- 没有 B 帧时 PTS == DTS
- 有 B 帧时 DTS 单调递增，PTS 可能跳动
- time_base 的作用：将整数 PTS 转为真实时间

### 6.2 简单的音视频同步器

**文件**：`av_sync.c`（OC，macOS）

**功能**：解码一路视频 + 一路音频，视频按音频时钟同步显示。

**知识点**：

- **音频时钟**：音频播放是匀速的（硬件时钟驱动），所以用音频作为主时钟
- **视频同步逻辑**：
  - 视频帧 PTS < 音频时钟 → 丢帧（追不上了）
  - 视频帧 PTS > 音频时钟 → 等待（还没到时间）
  - 差值在阈值内 → 正常显示
- `AVSampleBufferDisplayLayer` 的 `enqueue` 时机

- [ ] 什么是 clock drift（时钟漂移）？怎么处理？
- [ ] 直播场景的音视频同步和点播有什么不同？

## 模块 7：网络传输基础（C）

**目标**：理解 Socket 通信，为推流/拉流打基础。

### 7.1 TCP 文件传输

**文件**：`tcp_server.c` + `tcp_client.c`

**功能**：服务端发文件，客户端收文件并保存。

**知识点**：

- socket / bind / listen / accept / connect
- TCP 字节流：没有消息边界，需要自己分包
- 粘包处理：长度前缀协议

### 7.2 UDP 视频帧传输

**文件**：`udp_sender.c` + `udp_receiver.c`

**功能**：发送端读取 YUV 帧，UDP 发送；接收端接收并显示。

**知识点**：

- UDP 无连接、不可靠、有最大包长（MTU 限制）
- 大帧需要分片（一帧 1280×720 YUV = 1.3MB，远超 UDP 包大小）
- 丢包处理、乱序处理

### 7.3 简单的 HTTP-FLV 拉流

**文件**：`http_flv_reader.c`

**功能**：通过 HTTP GET 请求一个 FLV 直播流地址，解析 FLV Tag。

**知识点**：

- HTTP 长连接 / chunked transfer
- FLV 流式传输：不需要 seek，持续读 Tag
- 这就是直播拉流的基本原理

## 模块 8：RTMP 协议（C）

**目标**：理解 RTMP 协议细节，实现一个最简推流器。

### 8.1 RTMP 握手

**文件**：`rtmp_handshake.c`

**功能**：实现 RTMP 的 C0/C1/C2 握手过程。

**知识点**：

- C0/S0：版本号（1 字节）
- C1/S1：时间戳 + 零 + 随机数据（1536 字节）
- C2/S2：对端的 timestamp echo 回去
- 握手完成后进入 chunk stream

### 8.2 AMF 编码

**文件**：`amf_encoder.c`

**功能**：实现 AMF0 编码，构造 `connect`、`createStream`、`publish` 命令。

**知识点**：

- AMF0 类型标记（Number=0x00, String=0x02, Object=0x03...）
- RTMP 命令消息格式
- `connect` 命令需要携带的参数（app、tcUrl、flashVer...）

### 8.3 推送 FLV Tag 到 RTMP

**文件**：`rtmp_pusher.c`

**功能**：读取本地 FLV 文件，通过 RTMP 推送到服务器。

**知识点**：

- Chunk Stream：大消息拆分成固定大小的 chunk
- chunk basic header + message header + extended timestamp
- Sequence Header（SPS/PPS）必须第一个发
- Audio Sequence Header（AAC 配置）必须第一个发

### 8.4 完整推流器

**文件**：`rtmp_publisher.c`

**功能**：摄像头采集 → 编码 → RTMP 推流（可以复用 WorkLabs 的采集模块）。

- [ ] 推流前为什么要先发 Sequence Header？

### 9.2 Metal：渲染一张 YUV420P 图像

**文件**：`WLMetalYUVRenderer`

**功能**：将 YUV420P 数据通过 Metal 渲染为 RGB 图像。

**知识点**：

- 采样器（sampler）的使用
- 这就是 `WLMetalPreviewShaders` 在做的事

### 9.3 Metal：灰度 + 边缘检测滤镜

**文件**：`WLGrayscaleFilter` + `WLEdgeDetectFilter`

**功能**：在 WorkLabs 管线中加一个 GPU 滤镜。

**知识点**：

- 卷积核：Sobel 边缘检测（3x3 卷积）
- 多 pass 滤镜链：离屏渲染 + 中间纹理
- 这就是 `WLStreamFilterProtocol` 的实现思路

### 9.4 OpenGL：同样的事用 OpenGL 做一遍

**知识点**：

- OpenGL 渲染管线：VAO → VBO → Vertex Shader → Rasterization → Fragment Shader → Framebuffer
- 纹理绑定与采样
- OpenGL vs Metal 的设计理念差异
- 很多公司还在用 OpenGL ES，面试会问
